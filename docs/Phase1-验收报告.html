后端能力

  • 模块化单体：internal/modules/<domain> 每模块 handler / service / repository / dto / model / router 六件套；auth 与 user 完整实现，其余 10 个业务域以 501 占位模块注册。
  • 统一响应信封：{code, message, data, traceId}；业务错误码集中于 pkg/errs，Code → HTTP 状态映射集中于 pkg/httpx。
  • 认证闭环：注册 / 登录 / 刷新 / 登出，JWT 双 Token（access + refresh，typ 声明强校验），bcrypt 口令哈希，登录失败统一返回「账号或密码不正确」以防账号枚举。
  • RBAC 骨架：RequireAuth / RequireRole 中间件，CurrentUser 上下文注入。
  • 可观测性：链路 ID 贯穿请求、zap 结构化日志（含 GORM 桥接）、panic 恢复、连接串自动脱敏。
  • 数据库：GORM + golang-migrate，SQL 经 go:embed 内嵌二进制；首个迁移建 users 表（含部分唯一索引 WHERE deleted_at IS NULL）并附可回滚 down 脚本；种子账号三个。

前端能力

  • 管理后台：登录页 → 工作台（业务域进度 + 后端健康状态）→ 用户管理（分页 / 关键字 / 角色 / 状态筛选）→ 401 自动续期与跳转。
  • 讲师工作台：同构实现，视觉上以学术金区分。
  • uni-app：uni.request 自实现传输层（小程序无 XMLHttpRequest），tabBar 两页，可编译微信小程序与 H5。
  • 共享层：设计令牌与 Element Plus 主题覆盖、接口 SDK（Bearer 注入 / 信封拆解 / 401 自动续期与并发去重）、类型与常量。

04工程门禁

本轮补齐了 Phase 1 清单中三项此前未落地的基础设施，均由 CI 强制执行。

1契约闭环

swag 注解 → OpenAPI → 前端契约类型自动生成，一条 make sdk 完成。

2静态检查

golangci-lint v2 配置，7 类「能发现真实缺陷」的检查器，格式交给 gofmt + goimports。

3提交门禁

Husky + lint-staged 自动修复与格式化，commitlint 强制提交信息规范。

契约闭环

生成链为 swag（Swagger 2.0）→ swagger2openapi → openapi-typescript。swag 目前没有任何 OpenAPI 3.x 输出选项，而 openapi-typescript 只接受 3.x，因此中间必须做一次规范转换。

生成产物 schema.d.ts 与 @yanmai/shared 中的手写类型由 contract.ts 做编译期断言：后端删除或改名字段会在 pnpm typecheck 阶段直接报错，而不是等到运行时。断言方向取「前端声明的字段是否仍存在于契约中」——后端新增字段属兼容变更，不报警。

已验证断言真实有效（负向测试） 手动删除契约中的 phone 字段后，编译报出 contract.ts(68,10): error TS2344: Type 'false' does not satisfy the constraint 'true'；恢复后即消失。这一验证过程还暴露了一个陷阱：TypeScript 会跳过「未被引用的类型别名」的约束求值，因此断言必须写成值级声明。

06遗留与阻塞

阻塞项（需外部条件解决）

阻塞现象影响解决路径
云 PostgreSQL 本机实测确认无任何 PostgreSQL：psql / pg_ctl 不存在、5432 端口未监听、无相关系统服务 验收标准 ①② 无法完成；服务启动即执行迁移，缺库时按设计明确报错退出 提供连接串并填入 services/api/.env.local 的 DATABASE_URL
GitHub 账号锁定 全部 CI job 在启动阶段失败，零步骤记录，官方注解原文：「The job was not started because your account is locked due to a billing issue.」 验收标准 ④ 无法完成；CI 的实际执行逻辑无法得到验证 处理账号账单：https://github.com/settings/billing

技术债（不阻塞，建议尽早处理）

  • Go 32 位：见第 05 节，建议 Phase 2 前升级。
  • 请求方法仍为手写：@yanmai/api-client 的模块方法手写、类型由 OpenAPI 生成。接口数量上来后可切换为完全生成。
  • 依赖树 peer 警告：@vueuse/core@15 要求 vue@^3.5，而 uni-app 端锁定 vue@3.4.21。构建与运行均正常，暂不处理。
  • 教师端业务为空：当前仅有登录与工作台骨架。
  • 管理后台未做代码分割：主包体积偏大。
  • 无 E2E：Playwright 用例待补。

已识别的设计取舍（非缺陷）

  • 登出为无状态：服务端暂无 Token 黑名单，由客户端丢弃令牌。服务端失效依赖 Redis，排在 Phase 2。
  • 缺 REDIS_ADDR 时队列降级禁用：asynq 仅生产者侧就绪，消费者待后续阶段。
  • 迁移失败即拒绝启动：不允许在未迁移的库上对外服务，这是有意为之的失败模式。
